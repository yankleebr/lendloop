# Current Feature: Loan Notifications (n8n Workflow 1, DEV)

Spec: `context/features/loan-notifications.md`

## Status

In Progress

## Goals

- `automationLogs` table (`loanId`, `kind`, `event`, `recipientId`, `idempotencyKey`, `status` pending/sent/failed, `attempts`, `lastError?`, `lastStatusCode?`, `occurredAt`, `updatedAt`, `nextAttemptAt?`, `sentAt?`) with indexes `by_idempotency_key`, `by_loan`, `by_kind_status`; written only by `emitLoanEvent` (inside mutations) and `notifications.recordAttempt`
- One event per loan creation and status change: `loans.request` emits `loan.requested`; `transitionLoan` emits `loan.<status>` for approve/reject/cancel/markReturned and every auto-reject (`period_taken`, `tool_removed` from owner and admin removal); nothing emitted when the mutation throws
- Recipients per the Event Catalog (whoever did not act); exactly one recipient per row
- Payload `version: 1` with exactly the documented keys; `counterpart` = `publicUser` only, `recipient` = `publicUser` + own `email` (or `null`); never the counterpart's email, `tokenIdentifier` or role
- Idempotent: same key → one row; a `sent`/`failed` row is never sent again
- `convex/lib/hmac.ts`: `hmacSha256Hex`, `signWebhook` (`v1=<hex HMAC-SHA256(secret, ts + "." + body)>`, secret as UTF-8 bytes), constant-time `verifyWebhookSignature` (Web Crypto verify, 300 s tolerance both directions)
- `convex/notifications.ts` (default runtime, no public functions): `deliver` (internalAction, 15 s `AbortController`, `redirect: "manual"`, `X-LendLoop-Event-Id` / `-Timestamp` / `-Signature` headers, body = exact signed string), `getDelivery` (internalQuery), `recordAttempt` (internalMutation)
- Retry classification (Decision 7) and backoff `[30 s, 2 min, 10 min, 30 min]` ±20 % jitter, `Retry-After` honored (cap 30 min), `MAX_ATTEMPTS = 5` → `failed` with short `lastError` code
- Missing/invalid `N8N_*` env → `failed` / `not_configured`, no `fetch`, user mutation unaffected
- Removal budget: over `MAX_EVENTS_PER_TRANSACTION = 900` → extra rows `failed` / `event_budget`, removal still succeeds
- n8n `[DEV]` WF1: Raw Body webhook → Crypto node (`HMAC DEV`) → `timingSafeEqual` + 300 s window → mock notify (always) → Gmail (`Gmail DEV`, Sender Name "LendLoop", `[DEV]` subject, Retry On Fail 3×) when the recipient has an email; responds 200/400/401 (500 when Gmail finally fails)
- Sanitized export `n8n/workflows/loan-notifications.dev.json` (credential refs only, no `pinData`, no emails/secrets)
- Docs: `project-overview.md` (final `automationLogs` shape), `CLAUDE.md` (secrets, Gmail credentials, NEVER list), `.env.example` comment
- convex-test coverage (`hmac.test.ts`, `notifications.test.ts`; existing suites never reach real `fetch`); webhook-auditor no critical/high; lint/test/build pass; no new npm package or Convex component

## Notes

- Everything against **DEV**. No `--prod` command; PROD steps (`HMAC PROD`, `Gmail PROD`, `[PROD]` workflow, Convex prod env vars) only when the user asks
- PROD impact on merge: new table + internal functions; without `N8N_*` env vars every PROD event is logged `failed` / `not_configured`, user flows unchanged, no backfill
- User prerequisites before the end-to-end check: n8n Cloud account, secret + `HMAC DEV` credential, dedicated LendLoop Gmail account + `Gmail DEV` credential, published `[DEV]` WF1, `N8N_WEBHOOK_URL` / `N8N_WEBHOOK_SECRET` in Convex DEV env. Convex code can be built and unit-tested before (tests mock `fetch`)
- Outbox pattern (Decision 9): row inserted + `deliver` scheduled in the same transaction; key `notification:<loanId>:<event>`
- Convex is the single dedupe point; delivery is at-least-once (no n8n Remove Duplicates — Decision 8)
- Retryable: network, timeout, 404, 408, 409, 425, 429, 5xx, `internal`. Final: 3xx, 400, 401, 403, 410, 413, 422, other 4xx, `not_configured`, `loan_missing`
- `lastError` is a short code only; log lines contain only `logId`, attempt, outcome code and delay — never URL, secret, signature, body, names or emails
- Constants in `convex/lib/automationRules.ts`; validators (`LOAN_EVENT_TYPES`, `AUTOMATION_KINDS`, `AUTOMATION_STATUSES`) in `convex/lib/validators.ts`
- Tests: check that `vi.stubEnv` reaches convex-test functions (else a mockable config getter); full fake timers + `finishAllScheduledFunctions(vi.runAllTimers)`; existing loans/admin/tools suites stub `N8N_WEBHOOK_URL` to `""`; the event-budget test may need a mockable lower budget
- n8n Code node: if `require('crypto')` fails on the Cloud instance, stop and report (no `===` fallback)
- Out of scope: reminders, `convex/http.ts`, error workflow, activity UI (bonus F), listing-removed notification to the owner, resend/sweeper, workpool/action-retrier
